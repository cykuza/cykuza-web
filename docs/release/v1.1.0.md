# Release notes — `v1.1.0`

**Status:** ready to ship (security-parity line)  
**Package version:** `1.1.0`  
**Predecessor:** [v1.0.0-pre-parity](./v1.0.0-pre-parity.md) @ `8a62944`

This release brings cykuza-web to the same *security level* as cykuza-extension (S0–S11 bar), adapted for a browser Next.js app (session vault, no MV3 host permissions).

## Highlights

- **Next.js 16** + **React 19**; `proxy.ts` (HTTPS redirect in production)
- **Exact crypto pins:** `@scure/bip39@2.2.0`, `bip32@5.0.1`, `bitcoinjs-lib@7.0.1`, `ecpair@3.0.1`, `@bitcoinerlab/secp256k1@1.2.0`, `hash-wasm@4.12.0`
- **CI:** `npm audit --audit-level=high` → lint → test → build (no Dependabot)
- **Seed entropy:** default 24-word CSPRNG; `mixed` / `user` modes; import 12|24; backup quiz
- **BIP39 passphrase:** optional on create/mnemonic import; never stored; unified unlock failures
- **Session lock:** 5‑minute idle + visibility/pagehide; password policy ≥12
- **Vault:** Argon2id v2 seals; legacy PBKDF2 open → migrate on unlock
- **Send safeguards:** suffix-6 confirm, address book, daily spend, large-send ack (domain-enforced)
- **Electrum trust:** dual balance/UTXO fingerprint + dual broadcast txid; fail-closed `verify_off` / `degraded`
- **UX:** mnemonic import chooses 12/24 on a dedicated screen before word fields
- **Supply chain:** `npm run hash:release-inputs` (lockfile SHA-256)

## Platform notes (Vercel)

- Framework: Next.js (see root `vercel.json`)
- Do **not** use `output: 'standalone'` for Vercel
- Security headers live in `next.config.js` (CSP includes `wasm-unsafe-eval` for Argon2id)
- Required env: `NEXT_PUBLIC_ELECTRUMX_MAINNET` (comma-separated WSS); optional testnet / rate-limit vars

## Breaking / migration notes for users

- Existing session vaults open as legacy and rewrite to Argon2id v2 on successful unlock
- New wallets default to **24** words and BIP84 `m/84'/802'/0'/0/0`; import still discovers the pre-W0 legacy derivation when funded
- With **two or more** Electrum endpoints, dual verify is **required** (default on); turning it off blocks refresh/send
